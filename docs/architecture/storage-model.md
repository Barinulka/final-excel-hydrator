# Storage Model

## Цель документа
Этот документ фиксирует актуальную модель хранения после удаления `Project`.

Storage model должна отражать согласованную доменную модель, а не текущий UI. На этом этапе мы проектируем таблицы, связи, ограничения и правила хранения данных.

## Принципы
* PostgreSQL является основной БД приложения.
* Таблицы проектируются вокруг доменных блоков: FinancialModel, TimeParams, Investments.
* Данные финансовых вкладок хранятся в соответствующих таблицах.
* Доступные financial tabs и investment categories определяются кодом приложения, а не строками в БД.
* Расчетные значения не хранятся, если их можно надежно пересчитать из сохраненных исходных данных.
* Денежные суммы хранятся в рублях как точные decimal/numeric значения, не как float.
* Месяц хранится как date с первым днем месяца.
* Enum-значения на первом этапе хранятся как varchar и валидируются application layer. Для стабильных enum-ов можно добавить DB CHECK constraints.
* `created_at` и `updated_at` являются audit metadata и не должны участвовать в бизнес-логике.
* FinancialModel принадлежит User напрямую.
* Удаление FinancialModel может каскадно удалять принадлежащие ей доменные блоки.

## Общие соглашения
* Внутренние primary keys: `bigint identity`.
* Публичные идентификаторы: `short_id varchar(10)`.
* `short_id` генерируется backend-ом, не зависит от названия и не меняется при переименовании.
* `short_id` имеет фиксированную длину 10 символов.
* `short_id` использует lowercase-алфавит `23456789abcdefghjkmnpqrstuvwxyz`, без похожих символов `0/O`, `1/I/l`.
* Уникальность `short_id` защищается unique constraint в БД в рамках таблицы сущности.
* При collision application layer повторяет генерацию `short_id`.
* Даты доменных периодов: `date`.
* Audit timestamps: `timestamp without time zone`.
* Для audit timestamps используется `Gedmo\Timestampable\Traits\TimestampableEntity`, поэтому поля `created_at` и `updated_at` мапятся как `TIMESTAMP(0) WITHOUT TIME ZONE`.
* Статусы и закрытые множества: `varchar`.
* Поля с рублями получают суффикс `_rub`.
* Формат отображения сумм является настройкой FinancialModel для output/presentation и не меняет хранимые значения.

## Tables

## users

### Назначение
Хранит пользователей приложения. Административный доступ задается ролями пользователя, отдельная таблица `admin_users` не вводится.

### Columns
* `id bigint primary key generated by default as identity`
* `email varchar(180) not null`
* `password varchar(255) not null`
* `roles jsonb not null`
* `created_at timestamp without time zone not null`
* `updated_at timestamp without time zone not null`

### Constraints
* `email` должен быть уникальным.
* `email` не должен быть пустым.
* `roles` должен содержать только допустимые значения `UserRole`.

### Indexes
* unique index на `email`

### Relations
* User имеет много FinancialModel через `financial_models.owner_id`.

### Notes
* Роли валидируются application layer.
* Для первого slice достаточно ролей `user`, `admin`, `superAdmin`.
* Колонка `password` хранит password hash для Symfony Security, а не исходный пароль.

## financial_models

### Назначение
Хранит финансовые модели пользователя.

### Columns
* `id bigint primary key generated by default as identity`
* `owner_id bigint not null`
* `short_id varchar(10) not null`
* `title varchar(255) not null`
* `description text null`
* `version_number integer not null`
* `source_model_id bigint null`
* `status varchar(32) not null`
* `amount_display_format varchar(16) not null`
* `created_at timestamp without time zone not null`
* `updated_at timestamp without time zone not null`
* `archived_at timestamp without time zone null`

### Constraints
* `owner_id` references `users(id)` on delete restrict.
* `source_model_id` references `financial_models(id)` on delete set null.
* `short_id` должен быть уникальным среди FinancialModel.
* `short_id` должен иметь длину 10 символов.
* `title` не должен быть пустым.
* `version_number` должен быть положительным.
* `owner_id, version_number` должны быть уникальны вместе.
* `status` должен соответствовать `FinancialModelStatus`.
* `amount_display_format` должен соответствовать `AmountDisplayFormat`.
* Новая FinancialModel создается со статусом `active`.
* Новая FinancialModel получает `amount_display_format = wholeRubles`.

### Indexes
* unique index на `short_id`
* unique index на `owner_id, version_number`
* index на `owner_id`
* index на `owner_id, status`
* index на `source_model_id`

### Relations
* FinancialModel принадлежит User.
* FinancialModel имеет ровно один TimeParams.

### Notes
* `amount_display_format` применяется к output конкретной FinancialModel: UI-таблицам, summary, Excel export и будущим отчетам.
* `amount_display_format` копируется при копировании FinancialModel.
* `amount_display_format` не влияет на расчеты и сохраненные денежные значения.
* FinancialModel может иметь не более одного InvestmentBlock.
* FinancialModel может ссылаться на исходную модель через `source_model_id`.
* `source_model_id` хранит происхождение копии, но не влияет на расчеты.
* При удалении исходной модели скопированная модель не удаляется.
* Копирование FinancialModel будет отдельным future use case.
* Расчет следующего `version_number` должен быть transaction-safe: через lock или retry при unique violation.
* Архивированная FinancialModel остается в общем списке моделей, но сортируется после активных моделей.
* Архивированная FinancialModel доступна для просмотра и Excel export в read-only режиме.
* Архивированная FinancialModel недоступна для редактирования.
* Для архивированной FinancialModel доступны только операции восстановления и окончательного удаления.

## time_params

### Назначение
Хранит обязательные временные параметры FinancialModel.

### Columns
* `id bigint primary key generated by default as identity`
* `financial_model_id bigint not null`
* `investment_start_month date not null`
* `investment_duration_months integer not null`
* `commercial_operation_duration_months integer not null`
* `forecast_step varchar(16) not null`
* `created_at timestamp without time zone not null`
* `updated_at timestamp without time zone not null`

### Constraints
* `financial_model_id` references `financial_models(id)` on delete cascade.
* `financial_model_id` должен быть уникальным.
* `investment_start_month` должен быть первым днем месяца.
* `investment_duration_months` должен быть положительным.
* `commercial_operation_duration_months` должен быть положительным.
* `forecast_step` должен соответствовать `ForecastStep`.

### Indexes
* unique index `time_params__financial_model_id__uniq` на `financial_model_id`

### Relations
* TimeParams принадлежит FinancialModel.

### Notes
* Производные даты не хранятся.
* Месячный временной ряд не хранится.
* Флаги инвестиционной и операционной деятельности не хранятся.
* На первом этапе `forecast_step` сохраняется, но не меняет месячный расчетный ряд.

## messenger_messages

### Назначение
Инфраструктурная таблица Symfony Messenger для асинхронных сообщений и failed transport.

Эта таблица не является частью доменной модели FinancialModel и не должна использоваться для хранения финансовых данных.

### Notes
* Таблица появляется в первой миграции из-за `symfony/doctrine-messenger` и doctrine transport.
* Оставляем таблицу как инфраструктурную часть Symfony setup.
* Доменные use cases не должны напрямую читать или писать `messenger_messages`.

## investment_blocks

### Назначение
Хранит корневой блок Investments для FinancialModel.

### Columns
* `id bigint primary key generated by default as identity`
* `financial_model_id bigint not null`
* `created_at timestamp without time zone not null`
* `updated_at timestamp without time zone not null`

### Constraints
* `financial_model_id` references `financial_models(id)` on delete cascade.
* `financial_model_id` должен быть уникальным.

### Indexes
* unique index на `financial_model_id`

### Relations
* InvestmentBlock принадлежит FinancialModel.
* InvestmentBlock имеет много InvestmentItem.

### Notes
* InvestmentBlock не обязателен для создания FinancialModel.
* В первом slice можно создать InvestmentBlock лениво при первом сохранении Investments.

## investment_items

### Назначение
Хранит инвестиционные объекты и расходы, введенные пользователем.

### Columns
* `id bigint primary key generated by default as identity`
* `investment_block_id bigint not null`
* `category varchar(64) not null`
* `title varchar(255) null`
* `initial_cost_rub numeric(20,2) not null`
* `vat_applied boolean not null default false`
* `useful_life_years integer null`
* `deferred_expense_write_off_years integer null`
* `lease_term_months integer null`
* `depreciation_enabled boolean null`
* `property_taxable varchar(16) null`
* `property_tax_base varchar(32) null`
* `cadastral_value_rub numeric(20,2) null`
* `land_taxable varchar(16) null`
* `vehicle_taxable varchar(16) null`
* `vehicle_power_hp integer null`
* `position integer not null default 0`
* `created_at timestamp without time zone not null`
* `updated_at timestamp without time zone not null`

### Constraints
* `investment_block_id` references `investment_blocks(id)` on delete cascade.
* `category` должен соответствовать `InvestmentCategory`.
* `initial_cost_rub` должен быть больше 0.
* `useful_life_years` должен быть больше 0, если заполнен.
* `deferred_expense_write_off_years` должен быть больше 0, если заполнен.
* `lease_term_months` должен быть больше 0, если заполнен.
* `cadastral_value_rub` должен быть больше 0, если заполнен.
* `vehicle_power_hp` должен быть больше 0, если заполнен.
* `position` должен быть больше или равен 0.

### Indexes
* index на `investment_block_id`
* index на `investment_block_id, category`
* index на `investment_block_id, position`

### Relations
* InvestmentItem принадлежит InvestmentBlock.
* InvestmentItem имеет много InvestmentSchedulePeriod.

### Notes
* Правила обязательности полей по категориям валидируются application layer.
* `InvestmentTreatment` не хранится отдельным полем, потому что выводится из `category` и доменных правил.
* `title` nullable на уровне БД, потому что обязательность зависит от категории.
* НДС на первом этапе хранится как boolean-признак строки. Ставка НДС не хранится в InvestmentItem.
* На первом этапе ставка НДС является code-defined значением `22%`.
* На первом этапе инвестиции разрешены только в инвестиционной фазе.
* InvestmentItem может существовать без заполненного графика финансирования как черновик.
* Для расчета и Excel export график финансирования должен быть заполнен.
* Формат отображения `wholeRubles` или `decimalRubles` берется из FinancialModel и не влияет на сохраненные суммы.

## investment_schedule_periods

### Назначение
Хранит отмеченные пользователем месяцы финансирования для InvestmentItem.

### Columns
* `id bigint primary key generated by default as identity`
* `investment_item_id bigint not null`
* `period_month date not null`
* `created_at timestamp without time zone not null`

### Constraints
* `investment_item_id` references `investment_items(id)` on delete cascade.
* `period_month` должен быть первым днем месяца.
* `investment_item_id, period_month` должны быть уникальны вместе.

### Indexes
* unique index на `investment_item_id, period_month`
* index на `period_month`

### Relations
* InvestmentSchedulePeriod принадлежит InvestmentItem.

### Notes
* Сумма платежа в периоде не хранится, а рассчитывается из `initial_cost_rub` и количества отмеченных периодов.
* InvestmentSchedule не хранится отдельной таблицей; он представлен набором `investment_schedule_periods` для InvestmentItem.
* Если сумма не делится на количество отмеченных периодов без остатка, платежи округляются до 2 знаков, а остаток добавляется в последний отмеченный период.
* Проверка, что `period_month` попадает в инвестиционную фазу TimeParams, выполняется application layer.
* Если TimeParams изменились и `period_month` вышел за границы инвестиционной фазы, данные не удаляются автоматически. Блок считается требующим исправления.

## site_settings

### Назначение
Хранит административно управляемые presentation/content-настройки приложения.

### Columns
* `id bigint primary key generated by default as identity`
* `setting_key varchar(120) not null`
* `value text null`
* `value_type varchar(32) not null`
* `updated_by_user_id bigint null`
* `created_at timestamp without time zone not null`
* `updated_at timestamp without time zone not null`

### Constraints
* `setting_key` должен быть уникальным.
* `setting_key` не должен быть пустым.
* `value_type` должен быть одним из поддерживаемых типов настройки.
* `updated_by_user_id` references `users(id)` on delete set null.

### Indexes
* unique index на `setting_key`
* index на `updated_by_user_id`

### Relations
* SiteSettings может ссылаться на User, который последним изменил настройку.

### Notes
* Эта таблица не должна управлять списком financial tabs, расчетными правилами, enum-ами или storage model финансовых блоков.
* Для первого этапа достаточно key-value модели для простых текстов, meta-тегов и ссылок на изображения.
* Если админка начнет превращаться в CMS, модель хранения нужно будет проектировать отдельно.

## Deliberately Not Stored
* Производные даты TimeParams: `investment_end_date`, `commercial_operation_start_date`, `commercial_operation_end_date`, `model_end_date`.
* Месячные периоды модели.
* Флаги инвестиционной и операционной деятельности.
* Расчетные результаты CAPEX, НЗС, амортизации и списания РБП.
* Summary cards.
* Chart data.
* Excel export payload.
* Округленные значения, подготовленные только для отображения.
* Список financial tabs.
* Investment category definitions как отдельная таблица.
* Investment treatment как независимое поле InvestmentItem.
* UI-состояния: active tab, раскрытые accordion, состояние modal.
