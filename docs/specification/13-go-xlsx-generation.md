# 13. Генерация XLSX в Go

## Цель

Заменить mock Excel generator на реальную генерацию `.xlsx` через Go.

Symfony по-прежнему не генерирует Excel. Symfony создает `ExcelExport`, сохраняет snapshot `CalculationResultPayload` и отдает его worker-у через internal API.

## Библиотека

Для генерации используется:

```text
github.com/xuri/excelize/v2
```

Причины выбора:

- популярная Go-библиотека для `.xlsx`;
- умеет sheets, стили, форматы дат, формулы, data validation;
- позволяет дальше двигаться к шаблонному Excel export без PhpSpreadsheet.

## Что реализовано

Go worker:

1. Получает pending export-задачу.
2. Переводит ее в `processing`.
3. Передает в generator:
   - `PendingExport` с `CalculationResultPayload`;
   - `ProcessingExport` со статусом обработки.
4. Создает `.xlsx`.
5. Возвращает `filePath`.
6. Помечает export как `completed`.

Если generator возвращает ошибку, worker помечает export как `failed`.

## Раскладка файла

Для таблицы `timeline` из `CalculationResultPayload` создаются листы:

```text
Входные данные
Временные параметры
```

Это приближает файл к примеру из ТЗ.

### Лист `Входные данные`

Используется структура:

```text
C2  ед измерения
A4  Дата начала инвестиций
C4  дата
D4  значение даты
A5  Длительность инвестиций
C5  мес.
D5  количество месяцев
A6  Длительность коммерческой работы
C6  мес.
D6  количество месяцев
A7  Шаг прогнозирования
C7  выбор
D7  мес.
A9  Дата окончания инвестиционной фазы
C9  дата
D9  значение даты
A10 Дата начала коммерческой эксплуатации
C10 дата
D10 значение даты
A11 Дата окончания коммерческой фазы
C11 дата
D11 значение даты
```

Данные берутся из timeline snapshot-а. Формулы Excel пока не используются как источник истины: расчет уже выполнен Symfony.

### Лист `Временные параметры`

Используется структура:

```text
C2  ед.измерения
A4  Начало месяца
A5  Окончание месяца
E4.. начало каждого периода
E5.. окончание каждого периода
A7:D10 ключевые даты проекта
A13 флаг инвестиционной деятельности
A14 флаг операционной деятельности
A15 флаг начала операционной деятельности
E13.. значения флагов
E14.. значения флагов
E15.. значения флагов
```

## Важное решение

Go worker не пересчитывает временные параметры.

Он только берет готовые строки:

- `period_start_date`;
- `period_end_date`;
- `investment_activity`;
- `operating_activity`;
- `operating_start`.

Эти строки приходят из `CalculationResultPayload`, который построил Symfony.

## Тесты

`generator_test.go` теперь:

- создает `.xlsx` во временной директории;
- открывает файл через `excelize.OpenFile`;
- проверяет листы и ключевые ячейки;
- не оставляет файлов в рабочей папке проекта.

## Проверка

```bash
cd go-services/excel-worker
go fmt ./...
go test ./...
SYMFONY_INTERNAL_BASE_URL=http://127.0.0.1:7777 STORAGE_ROOT_DIR=../../var/storage EXCEL_EXPORTS_DIR=excel-exports go run ./cmd/excel-worker
```

Ожидаемый результат:

- тесты зеленые;
- worker создает файл в корневой папке Symfony-проекта `var/storage/excel-exports/excel-export-{id}.xlsx`;
- в Symfony сохраняется относительный `filePath`: `excel-exports/excel-export-{id}.xlsx`;
- в файле есть листы `Входные данные` и `Временные параметры`;
- данные временной шкалы заполнены из `CalculationResultPayload`.

## Что сознательно отложено

- точное копирование всех стилей эталонного Excel-файла;
- формулы Excel как отображаемый слой;
- download endpoint;
- генерация остальных финансовых блоков;
- постоянный worker loop.
